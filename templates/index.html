🔊 Выход аудио

❓ Какое устройство выбрать и почему список короткий

Веб-плеер (в браузере) — независимый канал. Звук идёт через /stream, устройство выбирается в браузере (кнопка «По умолчанию»). Смена устройства в браузере работает только на localhost или HTTPS.

Аппаратный выход (сервер) — куда пишет sounddevice: радио, объявления, chime. Выбирайте физическое устройство (Realtek / USB-карта), а не виртуальный кабель, если не настраиваете микшер через VB-Audio.

⚠ Список устройств теперь содержит только WASAPI. WDM-KS и MME отфильтрованы, потому что WDM-KS не поддерживает блокирующий API (ошибка PaErrorCode -9999: Blocking API not supported yet).

Как избежать конфликта с SIP:

  • HardwareOutput → Realtek (встроенные динамики)
  • PJSIP → USB-звуковая карта (отдельное устройство)

Если оба используют одно устройство — WMME блокирует одно из них. Радио в браузере пропадает, chime может не играть.

📢 Служебные объявления

❓ Как загружать объявления и как они попадают в эфир

Как загрузить:

  1. Выберите файл (WAV / MP3 / OGG / FLAC / M4A, до 20 МБ).
  2. Введите описание — например, «Обед с 13:00».
  3. Заполните расписание: время с и (время до ИЛИ лимит повторов).
  4. Опционально — мин. интервал между показами (для «раз в час» поставьте 60).
  5. Нажмите ⬆ Загрузить. Первое объявление станет активным автоматически.

Как попадает в эфир: при сработке DTMF-метки (или по таймауту) движок выбирает объявление, у которого сейчас активное расписание и не исчерпан лимит. Радио плавно затухает, объявление играет, радио возвращается.

Ротация: если объявлений несколько и все сейчас playable — играет то, которое дольше всех не звучало. Кнопка 🎯 Приоритет ставит файл вне очереди (работает только пока оно в окне расписания).

Кнопка «📅 N распр.» — открывает список расписаний. У одного файла может быть несколько независимых расписаний (утреннее, вечернее, выходные).

⚠️ Расписание обязательно: время начала + одно из — время окончания или лимит повторов.
⏱ Интервал — минимальная пауза между показами одного файла (например, «24/день» + «60м» = раз в час).
💡 При загрузке создаётся первое расписание. Дополнительные можно добавить в таблице — кнопкой «📅 N распр.».

⚙ Настройки

Источник сигнала

❓ Чем отличаются «Интернет-поток» и «Устройство захвата»

Интернет-поток (URL) — радиостанция транслируется из сети. Вставьте прямую ссылку на MP3-поток. Примеры для теста:

  • https://ice5.somafm.com/vaporwaves-128-mp3
  • http://stream.radioparadise.com/mp3-128

Устройство захвата — локальный микрофон, линейный вход, FM-тюнер или виртуальный кабель (VB-Audio). Выбирается в выпадающем списке.

⚠ В списке устройств теперь только WASAPI. WDM-KS и MME отфильтрованы, потому что не поддерживают блокирующий поток, используемый в проекте.

При смене источника на лету движок перезапускается автоматически — в логе появится restarting.

🔁 Резервные каналы

❓ Как работает автоматическое резервирование

Если основной поток «упал» (нет данных дольше, чем таймаут) — движок автоматически переключается на первый резервный URL. Через retry секунд пробует вернуться на основной.

  • Таймаут — сколько секунд без данных считать аварией (рекомендуется 10–15)
  • Retry — как часто пробовать вернуться (рекомендуется 60)
  • Резервные URL — упорядоченный список, проверяются по очереди

В панели «Сейчас» появится 🟡 резерв, а в «Источник» — имя резервного канала.

Детекторы субтонов

❓ Что такое CTCSS, DCS и DTMF

DTMF (Dual-Tone Multi-Frequency) — стандарт «телефонных кнопок». В радиовещании используется как маркер вставки: станция в определённые моменты передаёт последовательность цифр (например, 3957 для Русского Радио). Детектор распознаёт метку и запускает объявление.

  • Поле «DTMF-метки» — список кодов, которые слушаем. Длина 2–10 символов, разрешены 0-9, *, #, A-D.
  • Кнопка ▶ рядом с меткой — тестовый запуск объявления без ожидания сигнала в эфире.

CTCSS — непрерывный низкочастотный тон (67–254 Гц), используется в радиосвязи для разделения каналов.

DCS — цифровой код на месте CTCSS. В этом проекте реализован как второй частотный детектор (полноценный 23-битный декодер — в планах).

⚠ Для реального эфира CTCSS/DCS обычно не используются — основной триггер это DTMF.

Сканер находит CTCSS-частоты в потоке за последние 3 секунды. Оценка: 🟢 >0.05 уверенно, 🟡 >0.01 вероятно, ⚪ ниже — слабо.

📟 DTMF-метки (автоматизация вещания)

Добавьте метки, которые нужно слушать в эфире. Например, 3957 для Русского Радио. При совпадении автоматически запустится служебное объявление. Поддерживаются цифры 0-9, а также * # A B C D (2–10 символов).

📞 SIP / ЛСО

❓ Как настроить SIP-подключение

Шаг 1. Узнайте у администратора АТС (Asterisk / FreePBX / Yeastar / MikoPBX) три параметра:

  • SIP-домен — IP-адрес или имя сервера АТС (например, 10.72.102.1)
  • Логин — внутренний номер или SIP-extension (например, 77702)
  • Пароль — из настроек extension в АТС

Шаг 2. Заполните поля, нажмите 💾 Сохранить, затем ▶ Подключить.

Шаг 3. В логе сервера должно появиться:
[SIP] Регистрация: OK (код 200) — значит регистрация прошла. Лампочка на кнопке 📞 SIP станет зелёной.

⚠ Порт 5060/udp должен быть открыт на сервере и доступен из сети АТС. Если администратор АТС использует другой порт или TCP — укажите это в поле «Порт» и «Транспорт».

❓ Почему SIP перехватывает звук / куда идут радио и звонок

На сервере два независимых источника звука:

  • HardwareOutput (sounddevice) — радио + объявления + chime («плим-блим»)
  • PJSIP (pjsua2) — голос звонящего

Проблема: если оба используют одно и то же физическое устройство (например, Realtek), драйвер WMME блокирует одного из них. Звук в браузере (через /stream) пропадает, chime может не играть.

Решение: развести потоки по разным устройствам:

  • 🔊 Аппаратный выход (в «Выход аудио») → встроенные динамики Realtek
  • PJSIP → отдельная USB-звуковая карта / USB-наушники (настраивается в sip_client.py, строка setPlaybackDev(N))

Или используйте VB-Audio Cable как виртуальный микшер — тогда радио и SIP микшируются в один канал, но это требует ручной настройки Windows.

При входящем звонке радио плавно затухает, играет «плим-блим», затем SIP-звонок соединяется. Тест играет сигнал прямо сейчас — убедитесь, что радио/объявление приостановится.

📅 Расписания

❓ Как работают несколько расписаний

Один и тот же файл может звучать в разное время по разным правилам. Например:

  • Расписание 1: 09:00–12:00, будни, ≤5/день, интервал 30 мин
  • Расписание 2: 14:00–18:00, будни, ≤3/день, интервал 60 мин
  • Расписание 3: 10:00–16:00, выходные, ≤2/день

Движок на каждом срабатывании выбирает любое playable расписание этого файла по ротации — какое дольше не звучало. Счётчики у каждого расписания свои.

В таблице объявлений «Сегодня» и «Всего» — сумма по всем расписаниям.

📅 Расписание

❓ Правила заполнения расписания
  • Действует с — обязательно. Время начала окна.
  • Действует до — конец окна. Если оставить пустым, нужен лимит повторов, иначе объявление будет звучать круглосуточно.
  • Повторов в день — максимум показов за сутки. 0 = без ограничения.
  • Мин. интервал — минимальная пауза между показами этого расписания. Например, «лимит 24 / интервал 60» = раз в час, не более 24 раз в сутки.
  • Дни недели — отметьте, в какие дни правило действует. Если ничего не отмечено — все 7 дней.

Несколько расписаний на один файл — можно добавить в списке (кнопка «➕ Добавить расписание»). У каждого расписания свои счётчики и интервалы.

⚠ Удаление последнего расписания — файл останется на диске, но не будет звучать (нет окон). Кнопка «Удалить» в редакторе.
