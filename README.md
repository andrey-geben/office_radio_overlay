# 📻 Office Radio Overlay

> Система трансляции интернет-радио в офисе с автоматической вставкой служебных объявлений по управляющему субтону (CTCSS/DCS), поддержкой SIP-звонков (ЛСО) и резервных источников.

[![Python](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/)
[![Flask](https://img.shields.io/badge/flask-3.0+-green.svg)](https://flask.palletsprojects.com/)
[![License](https://img.shields.io/badge/license-MIT-lightgrey.svg)](LICENSE)

---

## 🎯 Что это

Проект позволяет использовать обычную интернет-радиостанцию как фоновое музыкальное сопровождение в офисе и **автоматически прерывать её** для служебных объявлений (например, «Обед с 13:00») при обнаружении специального сигнала — CTCSS-субтона в аудиопотоке. Также поддерживает:

- **Плавные переходы** радио ↔ объявление (fade-in / fade-out).
- **Автоматическую вставку по таймауту**, если сигнал не пришёл за N минут.
- **Расписание** для каждого объявления (время действия, лимит повторов в день).
- **SIP-интеграцию** (ЛСО): при входящем звонке радио приостанавливается, голос звонящего идёт в офисные динамики.
- **Резервные источники**: если основной поток радио упал — автоматически подключается резервный.
- **Веб-панель** с ретро-дизайном, стрелочными индикаторами, эквалайзером и управлением всеми параметрами.

## 🏗️ Архитектура

```
┌──────────────────────────────────────────────────────────────────┐
│                        ВЕБ-ПАНЕЛЬ (Flask)                        │
│  Авторизация · Настройки · Объявления · SIP · Fallback · Плеер  │
└──────────────────┬───────────────────────────────────────────────┘
                   │ /api/*
                   ▼
┌──────────────────────────────────────────────────────────────────┐
│                    ДВИЖОК (RadioOverlayEngine)                   │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────────────────┐   │
│  │ Источник     │  │ Детекторы    │  │ Микшер + Fade         │   │
│  │ (поток/устр.)│─▶│ CTCSS/DCS    │─▶│ (ducking envelope)    │   │
│  │ + Fallback   │  │ + Timeout    │  │                       │   │
│  └──────────────┘  └──────────────┘  └───────────┬───────────┘   │
│                                                   │              │
│  ┌──────────────┐  ┌──────────────────────────────┴───────────┐  │
│  │ SIP-клиент   │  │ Выходы: HTTP-стрим + HardwareOutput      │  │
│  │ (PJSIP)      │  │ (sounddevice)                            │  │
│  └──────────────┘  └──────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

**Потоки данных:**
1. Источник (Icecast/MP3 или локальное устройство) → аудио-чанки PCM.
2. Детектор CTCSS/DCS (алгоритм Гёрцеля) + опционально FFT для эквалайзера.
3. Микшер с огибающей fade-in/out (при активном объявлении).
4. Раздача:
   - HTTP `/stream` → браузерный плеер (с выбором устройства вывода).
   - `HardwareOutput` → `sounddevice` на серверную звуковую карту (для ЛСО).

## 🚀 Быстрый старт

### Требования

- **Python 3.10+**
- **FFmpeg** (для `pydub` — декодирование MP3)
- Windows / Linux / macOS

### Установка FFmpeg

**Windows:**
1. Скачайте [ffmpeg-release-essentials.zip](https://www.gyan.dev/ffmpeg/builds/) (или с [ffmpeg.org](https://ffmpeg.org/download.html)).
2. Распакуйте, например, в `C:\ffmpeg\`.
3. Добавьте `C:\ffmpeg\bin` в `Path` (Система → Переменные среды → Path → Изменить → Создать).
4. Перезапустите терминал, проверьте: `ffmpeg -version`.

**Linux:**
```bash
sudo apt install ffmpeg
```

**macOS:**
```bash
brew install ffmpeg
```

### Клонирование и установка

```bash
git clone https://github.com/your-username/office-radio-overlay.git
cd office-radio-overlay

python -m venv .venv
# Windows:
.venv\Scripts\Activate.ps1
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### Первый запуск

```bash
python main.py
```

Откройте [http://localhost:5000](http://localhost:5000). Логин по умолчанию — **admin / admin**.

> ⚠️ **Обязательно смените пароль** перед использованием в продакшене (см. раздел «Безопасность»).

## ⚙️ Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AUTH_USER` | Логин администратора | `admin` |

```powershell
$env:AUTH_USER="operator"

```

### Файл настроек

Все настройки автоматически сохраняются в `assets/settings.json`:

- Частоты и пороги CTCSS/DCS
- Параметры ducking и fade
- Источник радио (URL или устройство)
- Аппаратный выход
- SIP-данные (домен, логин, **пароль**)
- Резервные источники
- Флаги автозапуска

> 🔒 **Пароль SIP** хранится в plaintext. Не коммитьте `assets/settings.json` в git (файл в `.gitignore`).

### Список объявлений

Метаданные объявлений (расписание, счётчики, длительность) — в `assets/announcements.json`, сами файлы — в `assets/announcements/`.

## 📖 Как пользоваться

### 1. Настройка источника

**Карточка «Источник сигнала»:**
- **Интернет-поток** — вставьте URL MP3-потока (например, `https://ice5.somafm.com/vaporwaves-128-mp3`).
- **Устройство захвата** — выберите микрофон / линейный вход / виртуальный кабель.

**Резервные каналы (fallback):**
- Включите чекбокс, задайте таймаут (секунды ожидания без данных) и интервал retry.
- Добавьте URL резервных потоков.
- При падении основного движок автоматически переключится, а через `retry_main` секунд попробует вернуться.

### 2. Загрузка служебных объявлений

В карточке «Служебные объявления»:
- Выберите аудиофайл (WAV/MP3/OGG/FLAC/M4A, до 20 МБ).
- Введите описание.
- Опционально — **расписание**: «Действует с/до HH:MM», «Повторов в день» (0 = без лимита).
- Нажмите «Загрузить». Первое объявление автоматически становится активным.

### 3. Настройка детекторов

**CTCSS** — аналоговый субтон (67–254 Гц). Стандартный набор — 50 частот, полный список есть в `tone_detector.py` и таблице ниже.

**DCS** — цифровой код (пока реализован как второй частотный детектор, полноценный 23-битный декодер — в планах).

**Автоопределение субтона:** нажмите «🔍 Сканировать (3 сек)» — программа прогонит все 50 CTCSS-частот по буферу последних 3 секунд эфира и покажет топ-10 кандидатов. Оценка:
- 🟢 `>0.05` — уверенно
- 🟡 `>0.01` — вероятно
- ⚪ `<0.01` — слабо

Кнопка «Применить» на нужной строке выставит частоту в поле CTCSS.

### 4. Плавные переходы

В настройках детекторов:
- **Затухание (мс)** — время приглушения радио при старте объявления (по умолчанию 500).
- **Нарастание (мс)** — время возврата после окончания (по умолчанию 800).

Рекомендуемые значения для офиса: `300–800 / 500–1200`. Для важных объявлений — короче, чтобы привлечь внимание.

### 5. Таймаут без тона (fallback-триггер)

Если включён — программа вставит объявление даже без сигнала, если активного тона не было N секунд (например, 10 минут). Это защита от ситуаций «тон потерялся, а объявление нужно».

Таймер сбрасывается при:
- запуске движка,
- каждой сработке тона,
- каждой вставке (по тону или таймауту).

### 6. SIP / ЛСО

**ЛСО = Loudspeaker Announcement System** — система громкого оповещения.

Заполните форму SIP:
- Домен (например, `sip2sip.info` или IP вашей АТС)
- Логин, пароль, порт (обычно 5060), транспорт (UDP/TCP)
- Нажмите **💾 Сохранить**, затем **▶ Подключить**

**Что происходит при звонке:**
1. PJSIP принимает вызов автоматически.
2. Движок переходит в режим `SIP`, радио приостанавливается.
3. Голос звонящего идёт на **аудиоустройство сервера по умолчанию**.
4. После сброса звонка радио возобновляется.

**Тест на бесплатном провайдере:**
- Зарегистрируйтесь на [sip2sip.info](https://sip2sip.info/) или [linphone.org](https://www.linphone.org/).
- Заполните домен/логин/пароль в панели.
- Позвоните на этот аккаунт из MicroSIP, Zoiper или Linphone.

> 💡 Для реальной интеграции с офисной АТС (Asterisk/FreePBX/MikoPBX) запросите у админа отдельный SIP-extension.

### 7. Выходы аудио

**Веб-плеер** — кнопка «▶ Подключить» в карточке «Выход аудио». Аудио идёт через HTTP-стрим в ваш браузер. Можно выбрать устройство вывода (`setSinkId`) — но **только на localhost или HTTPS**.

**Аппаратный выход** — выбор устройства на сервере. Используется для:
- Подключения к офисному усилителю.
- ЛСО через SIP.
- Подачи в виртуальный кабель (VB-Audio, BlackHole) для стриминга на Icecast.

### 8. Автозапуск

Две галочки:
- **«Автозапускать движок при старте сервера»** — после рестарта сервера движок сразу начнёт трансляцию.
- **«Автозапускать SIP»** — SIP-клиент поднимется автоматически.

## 🔧 Требования и настройки по производительности

### Рекомендуемые параметры

| Параметр | Значение | Где менять |
|---|---|---|
| `SAMPLE_RATE` | 44100 Гц | `config.py` |
| `BLOCK_SIZE` | 1024 сэмпла | `config.py` |
| `STREAM_QUEUE_SIZE` | 20 чанков (~1 сек) | `config.py` |
| Интервал гистограммы | 80 мс | `engine.py::_update_spectrum` |

**Нагрузка на CPU** (Raspberry Pi 4 / Intel NUC):
- Без SIP: ~5–15 %.
- С SIP: +3–5 %.
- FFT эквалайзера: +1–2 %.

### Устройство воспроизведения для SIP

PJSIP использует **устройство по умолчанию** из ОС. Если на сервере несколько звуковых карт:

**Windows:** Панель управления → Звук → выбрать нужное устройство «По умолчанию».

**Linux:** `pavucontrol` или `pactl set-default-sink <name>`.

В будущих версиях — выбор через UI.

## 🐛 Диагностика

### Проблемы и решения

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: flask` | `pip install -r requirements.txt` |
| `Couldn't find ffmpeg` | Установите FFmpeg, перезапустите терминал |
| В браузере нет выбора устройства вывода | Используйте `localhost` или настройте HTTPS |
| SIP: `Failed to resolve '<domain>'` | Проверьте домен: `ping sip.example.com` в терминале |
| SIP: `401 Unauthorized` | Неверный логин/пароль. `SIP_USERNAME` — без `@domain` |
| SIP: `408 Request Timeout` | Порт 5060 закрыт. Попробуйте `SIP_TRANSPORT = "tcp"` |
| Радио молчит после старта | Проверьте URL потока, откройте в браузере — если не играет, URL недоступен |
| Объявления не срабатывают | Запустите «🔍 Сканировать» — возможно, частота CTCSS подобрана неверно |
| «Тон не приходит» | Включите таймаут fallback (10 минут) — объявление вставится по времени |

### Логи

Flask выводит запросы в консоль. Для детального лога добавьте в `main.py`:

```python
import logging
logging.basicConfig(level=logging.INFO,
                    format='%(asctime)s [%(levelname)s] %(name)s: %(message)s')
```

## 🔒 Безопасность

**Перед вводом в эксплуатацию:**

1. **Смените `AUTH_USER` и `AUTH_PASS`.** Пароль `admin/admin` — только для первого теста.
2. **Установите `SECRET_KEY`** через переменную окружения. Без него сессии Flask уязвимы.
3. **Настройте HTTPS** (для продакшена):
   - Nginx/Apache с Let's Encrypt (рекомендуется).
   - Или Flask с `ssl_context='adhoc'` (только для внутренней сети).
4. **Ограничьте доступ к порту 5000** — используйте reverse-proxy или firewall.
5. **Не коммитьте `assets/settings.json`** — там пароли.
6. **Используйте production WSGI** (gunicorn / waitress), а не Flask-сервер:

```bash
pip install waitress
# main.py в конце:
# from waitress import serve
# serve(app, host="0.0.0.0", port=5000, threads=8)
```
