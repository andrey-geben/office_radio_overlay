# 📻 Office Radio Overlay

> Система трансляции интернет-радио в офисе с автоматической вставкой служебных объявлений по управляющему субтону (CTCSS/DCS), поддержкой SIP-звонков (ЛСО), резервных источников и удалённого управления с любого ПК.

## 🎯 Что это

Обычная интернет-радиостанция играет фоном в офисе, а при появлении в эфире управляющего субтона (CTCSS/DCS) система **плавно приглушает музыку и вставляет служебное объявление** — «Обед с 13:00», «Через 5 минут планёрка» и т.п.

Ключевые возможности:

- **Один серверный выход** — звук идёт в звуковую карту сервера (усилитель, ЛСО, виртуальный кабель). Это единственный источник звука в помещении.
- **Удалённое управление** — админка открывается с любого ПК в сети; сервер продолжает играть даже при закрытом браузере.
- **Веб-плеер = монитор** — с удалённого ПК можно послушать, что реально звучит на сервере. На самой серверной машине плеер запрещён, чтобы не было двойного звука.
- **SIP / ЛСО** — входящий звонок: радио затухает, играет сигнал внимания (chime), выдерживается пауза, и только потом звонок соединяется. SIP-голос идёт в то же устройство, что и радио.
- **Служебные объявления** — плавное приглушение радио до 5 %, громкость объявления регулируется, расписание (окна, дни, лимит повторов, интервал), ротация и приоритет.
- **Резервные источники** — при падении основного потока автоматически включается резерв, затем попытка вернуться на основной.
- **Восемь тем оформления** — от «Black Technics» до McIntosh-приборов, Winamp, военного приёмника и CRT-терминала.
- **Живые приборы** — стрелочные индикаторы уровня/CPU/сети в стиле McIntosh; шкала NET считается от реальной скорости сетевой карты (100 Мбит/1 Гбит = 100 %).
- **Надёжный СТОП** — очистка звукового буфера, добивание FFmpeg, режим принудительной остановки.

## 🏗️ Архитектура

```
┌────────────────────────────────────────────────────────────────────┐
│                     ВЕБ-ПАНЕЛЬ (Flask, сервер)                     │
│  Авторизация · Настройки · Объявления · SIP · Fallback · Темы      │
└───────────────────┬────────────────────────────────────────────────┘
                    │ /api/*  (админ может быть на другом ПК)
                    ▼
┌────────────────────────────────────────────────────────────────────┐
│                    ДВИЖОК (RadioOverlayEngine)                     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────────────┐  │
│  │ Источник     │  │ Детекторы    │  │ Микшер + Fade            │  │
│  │ (поток/устр.)│─▶│ CTCSS/DCS    │─▶│ (ducking 5 %)            │  │
│  │ + Fallback   │  │ + Timeout    │  │                          │  │
│  └──────────────┘  └──────────────┘  └────────────┬─────────────┘  │
│                                                   │                │
│  ┌──────────────┐  ┌──────────────────────────────▼─────────────┐  │
│  │ SIP-клиент   │  │ Выходы: HardwareOutput (sounddevice)       │  │
│  │ (PJSIP)      │  │ + подписчики веб-плеера (у каждого своя    │  │
│  └──────────────┘  │   очередь — без заикания)                  │  │
│                    └────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────┘
```

**Поток данных:**

1. Источник (Icecast/MP3 или локальное устройство) → PCM-чанки.
2. Детектор CTCSS/DCS (алгоритм Гёрцеля) + FFT-спектр для эквалайзера.
3. Микшер с огибающей: радио приглушается, объявление добавляется.
4. Раздача:
   - `HardwareOutput` → звуковая карта **сервера** (усилитель/ЛСО);
   - `/stream` → веб-плеер каждого слушателя (только для мониторинга с удалённого ПК).

## 🚀 Быстрый старт

### Вариант 1: готовый exe (Windows)

1. Скачайте архив `OfficeRadioOverlay_v1.2.5_win64.zip` из [релизов](https://github.com/andrey-geben/office_radio_overlay/releases/latest).
2. Распакуйте в папку без кириллицы в пути (например, `C:\OfficeRadio\`).
3. Запустите `OfficeRadioOverlay.exe`.
4. Откройте панель: `http://<IP-сервера>:5000` (на сервере — `http://127.0.0.1:5000`).

Первый запуск проводит проверку окружения (FFmpeg, PortAudio, VB-Cable, права на запись) и показывает мастер: выбрать устройство вывода → проверить сигнал → запустить эфир.

> Второй экземпляр exe заблокирован: вместо ошибки занятого порта появится сообщение «программа уже запущена».

### Вариант 2: из исходников

Требования: **Python 3.10+**, **FFmpeg** в `PATH`.

```bash
git clone https://github.com/andrey-geben/office_radio_overlay.git
cd office_radio_overlay

python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate

pip install -r requirements.txt
python main.py
```

Логин по умолчанию — **admin / admin**, при первом входе система попросит сменить пароль.

## 🖥️ Сервер и админка на удалённом ПК

Это основной сценарий эксплуатации.

| Что | Где работает | Что делает |
|---|---|---|
| `OfficeRadioOverlay.exe` | сервер | держит движок, звук, SIP, объявления |
| Браузер админки | любой ПК в сети | настройка, запуск/стоп, объявления |
| Веб-плеер | удалённый ПК | **мониторинг** того, что звучит на сервере |
| Веб-плеер | сам сервер | **запрещён** (403), чтобы не было двойного звука |

- Закрытие админки **не останавливает** эфир — движок живёт в процессе exe.
- Список в «Аппаратный выход (сервер)» — это **устройства сервера** (их перечисляет сам сервер через PortAudio/WASAPI), а не удалённого ПК.
- Список в веб-плеере — это устройства **того браузера**, где он открыт.
- Разрешить плеер на сервере можно галочкой «Разрешить веб-плеер на сервере» в «Аппаратном выходе» (не рекомендуется).

## 🎨 Темы оформления

Переключатель — круглая ручка **«ТЕМА»** рядом с декоративными VOL/TONE. Темы идут по кругу, выбор хранится в браузере (`localStorage`), есть вариант в «Настройки → Цветовая схема».

| Тема | Настроение | Приборы |
|---|---|---|
| ☾ Тёмная (Black Technics) | тёмное дерево и золото | синяя подсветка |
| ☀ Светлая (Silver Technics) | шлифованный алюминий | синяя подсветка |
| 🎵 Winamp | классический Winamp 2.x | зелёная подсветка |
| 🎚 Студийный пульт | графитовый микшер, золотая линия | синяя подсветка |
| 🪖 Военный приёмник | олива, янтарный LCD | янтарная подсветка |
| 📻 Hi-Fi 70-х | орех, алюминий, засечки | янтарная подсветка |
| 🖥 Терминал (CRT) | фосфорный зелёный, скан-линии | зелёная подсветка |
| 🪵 Слоновая кость | кремовые панели, красное дерево | McIntosh, синяя |

Приборы во всех темах — в стиле McIntosh: чёрный корпус, стекло с подсветкой, риски шкалы, стрелка и латунная/стальная окантовка (цвета подстраиваются под тему).

Эквалайзер сворачивается кнопкой «−/+» в заголовке SPECTRUM; состояние запоминается.

## ⚙️ Конфигурация

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `AUTH_USER` | Логин администратора | `admin` |
| `AUTH_PASS` | Пароль администратора | `admin` |
| `SECRET_KEY` | Ключ сессий Flask | генерируется в `assets/secret.key` |
| `AUTO_OPEN_BROWSER` | `0` — не открывать браузер при старте | `1` |

### `assets/settings.json`

Создаётся автоматически, хранит:

- источник радио (`radio_url`, `source_type`, `input_device`);
- аудиовыход сервера (`hw_output_device`);
- детекторы (`tone_freq`, `dcs_freq`, пороги);
- микширование: `ducking_level` (радио при объявлении, по умолчанию **0.05**), `announcement_level`, `fade_out_ms`, `fade_in_ms`;
- SIP (`sip_domain`, `sip_username`, `sip_password`, `sip_port`, `sip_transport`, `sip_chime_enabled`, `sip_answer_delay_ms`);
- резервные источники (`fallback_sources`, таймауты);
- автозапуск (`auto_start_engine`, `auto_start_sip`);
- прочее (`dtmf_labels`, `web_player_allow_local`).

> 🔒 `sip_password` хранится в открытом виде — не коммитьте `assets/settings.json`.
> `assets/secret.key`, `assets/app.lock`, `logs/` и `assets/settings.json` исключены из git.

### Объявления

Метаданные — `assets/announcements.json`, файлы — `assets/announcements/`. Допустимые форматы: WAV, MP3, OGG, FLAC, M4A (до 25 МБ).

Логика показа:

- **есть сигнал** (CTCSS/DCS) — играет объявление из числа разрешённых в текущем окне расписания (ротация — то, что дольше не звучало);
- **сигнала нет** — срабатывает таймаут-триггер (если включён), то есть объявление вставляется по времени;
- во время SIP-звонка объявления не играют и не «висят» — пропускаются с записью в лог;
- входящий звонок во время объявления даёт фразе доиграть, затем включает chime.

## 📖 Как пользоваться

### Источник и резерв

В карточке «Источник сигнала» выберите интернет-поток или устройство захвата. Для резерва включите fallback, задайте таймаут без данных и список URL — движок переключится автоматически и попробует вернуться на основной через заданный интервал.

### Объявления и расписание

Загрузите файл, задайте описание и расписание: время действия, дни, лимит повторов, интервал (например, «24/день» + «60м» = раз в час). Кнопка «🎯 Приоритет» ставит файл вне очереди, пока он в окне расписания.

### Детекторы субтонов

CTCSS — аналоговый субтон 67–254 Гц (полная таблица 50 частот). DCS реализован как второй частотный детектор; полноценный 23-битный декодер — в планах. Кнопка «🔍 Сканировать (3 сек)» прогоняет 50 частот по буферу и показывает топ-10 кандидатов.

### SIP / ЛСО

Заполните домен, логин, пароль, порт и транспорт, сохраните и нажмите «Подключить».

При входящем звонке:

1. Радио плавно затухает.
2. Играет сигнал внимания `chime.wav`.
3. Выдерживается пауза `sip_answer_delay_ms` (по умолчанию 400 мс) — чтобы хвост сигнала не наложился на голос.
4. Отправляется `200 OK`, голос звонящего идёт в серверное устройство вывода.
5. После сброса звонка радио возвращается.

Если эфир остановлен, звонок соединяется сразу — ждать несуществующий сигнал не нужно. Если в момент звонка звучало объявление, оно доигрывается.

> Поле «Пауза после сигнала перед ответом, мс» находится в SIP-блоке (0…3000).

### Выходы аудио

**Аппаратный выход (сервер)** — выбор устройства сервера: усилитель, ЛСО, виртуальный кабель (VB-Audio/BlackHole) для стриминга. Если эфир запущен, а устройство не выбрано, сверху появляется предупреждение.

**Веб-плеер** — мониторинг с удалённого ПК; на сервере заблокирован.

### Автозапуск

«Автозапускать движок» и «Автозапускать SIP» — после рестарта сервера всё поднимется само.

## 🐛 Диагностика

| Симптом | Решение |
|---|---|
| `ModuleNotFoundError: flask` | `pip install -r requirements.txt` |
| `Couldn't find ffmpeg` | Установите FFmpeg, перезапустите терминал |
| Нет выбора устройства в веб-плеере | Нужен `localhost` или HTTPS (`setSinkId`) |
| Веб-плеер 403 | Открыт на самом сервере — это защита от двойного звука |
| Эфир запущен, а звука нет | Не выбрано «Аппаратное устройство» — смотрите баннер сверху |
| SIP: `Failed to resolve` | Проверьте домен: `ping sip.example.com` |
| SIP: `401 Unauthorized` | Неверный логин/пароль; логин — без `@domain` |
| SIP: `408 Request Timeout` | Порт 5060 закрыт; попробуйте транспорт TCP |
| «Тон не приходит» | Включите таймаут-триггер или проверьте частоту сканером |
| «Икание» звука | Проверьте FFmpeg в PATH; версия `audio_capture.py` должна использовать subprocess, а не pydub для потоков |
| Не запускается второй экземпляр | Это защита: закройте уже работающее окно `OfficeRadioOverlay.exe` |

**Логи:** `logs/app.log` (ротация 5 МБ × 5 файлов). Полезные строки:

- `[net] Скорость сетевой карты: …` — шкала NET;
- `СТОП: force=…, running=…, ffmpeg=…` — что осталось после остановки;
- `Объявление пропущено: идёт SIP-звонок…` — политика приоритетов;
- `Эфир остановлен — SIP соединяем без сигнала внимания`.

## 🔒 Безопасность

1. Смените пароль `admin/admin` при первом входе (система обязывает).
2. `SECRET_KEY` генерируется автоматически в `assets/secret.key`; при желании задайте свой через переменную окружения.
3. Для продакшена — HTTPS через reverse-proxy (Nginx/Apache + Let's Encrypt).
4. Ограничьте доступ к порту 5000 (firewall / VPN / reverse-proxy).
5. Не коммитьте `assets/settings.json` — там пароль SIP.
6. Для нагруженных установок используйте WSGI-сервер (waitress/gunicorn) вместо встроенного Flask.

```
├── sip_client.py            # SIP-клиент (PJSIP), логика ответа после chime
├── sip_worker.py            # PJSIP в отдельном процессе, JSON-команды
├── auth.py                  # @login_required / @admin_required
├── logging_setup.py         # Логи с ротацией
├── preflight.py             # Проверка окружения при старте

├── main.spec                # PyInstaller
├── tests/test_smoke.py      # Smoke-тесты
├── CHANGELOG.md
├── README.md
├── templates/               # index.html, login.html
├── static/                  # app.js, style.css (все темы)
└── assets/                  # создаётся: settings.json, users.json,

```
